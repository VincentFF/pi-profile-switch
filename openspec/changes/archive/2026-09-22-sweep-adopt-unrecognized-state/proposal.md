# Proposal

## Why

Extensions (observed case: `pi-mcp-adapter` writing `mcp-cache.json`) write files at runtime into `PI_CODING_AGENT_DIR` (the instance directory) that did not exist at mirroring time and were not generated by pi-profile. Per ADR-0010's contract, the startup sweep refuses to reclaim such dead directories and re-warns on every launch until the user manually moves the files and deletes the directory. Expanding the seed list is a prediction of the future that silently fails when an extension changes paths — rejected by ADR-0010; unconditional "absorb on reclaim" was also rejected because third-party records embed instance absolute paths (the pi-subagents ledger). A convergence path that makes no predictions and does not touch path-embedding records is needed.

## What Changes

- The startup sweep's disposition of unrecognized entries in dead instance directories changes from a uniform "keep + warn" to routing by content scan:
  - The entry's content (directories scanned recursively, with size/count limits) references its own instance path, or the scan exceeds limits, or the entry is an unconventional type such as socket/fifo → keep + warn (current behavior unchanged).
  - Otherwise, and the real agentDir has no same-named entry → move into the real agentDir (adoption), with a one-line notice to stderr. After adoption, the next launch turns it into a symlink via mirroring — permanently converged.
  - Otherwise (the real agentDir already has a same-named entry) → delete the instance copy (real wins), with a one-line notice to stderr. This branch only triggers in the race window where "the real entry appeared after that instance launched" and may lose content unique to the instance copy — an explicitly accepted cost.
- Unrecognized entries inside the managed `extensions/` directory keep the warn-only treatment and never participate in adoption.
- Sweeping stays best-effort; any single-directory failure does not block startup (unchanged).
- No new user-visible configuration fields: the routing criterion (whether the instance path appears) and the destination (the real agentDir) are both decided by the existing directory structure — no decision point a configuration could replace; scan limits are internal implementation constants.
- Add ADR-0012 recording this decision and its relationship to ADR-0010's rejection.

## Capabilities

### New Capabilities

(none)

### Modified Capabilities

- `launcher`: the "Stale instance sweep" requirement — the disposition of unrecognized entries changes from uniform keep-and-warn to content-scan routing into adoption, deletion (real wins), or keep-and-warn.

## Impact

- Code: `src/launcher/runtime-cleanup.ts` (`unrecognizedEntries` / `sweepEntry` routing logic), `test/launcher.integration.test.ts`.
- Docs: the sweep section of `docs/architecture/overview.md`, new ADR-0012 in `docs/adr/`, the `CONTEXT.md` glossary.
- No runtime dependency changes, no settings/catalog format changes, no CLI surface changes.

## Doc Impact

- `docs/prd.md`: none — product positioning, goals, and non-goals unchanged; sweep disposition strategy belongs to the behavior-contract and implementation layers.
- `docs/architecture/overview.md`: sync the instance sweep's disposition-strategy description (routing criteria and destinations).
- `CONTEXT.md`: add an "adoption" entry to the internal glossary (referenced by the spec, design, and architecture documents).
- `docs/adr/`: add ADR-0012 explaining why scan-gated conditional adoption does not overturn ADR-0010's "absorb on reclaim" rejection; ADR-0010's other decisions stay as-is and are not rewritten.
