# Proposal

## Why

The instance is defined in `CONTEXT.md` as "the runtime directory generated for one Pi process", but the 0.4.x implementation pinned it to `instances/<profile>/agent`, reusing the same path on every launch of the same profile. Three consequences coexist:

- Concurrent launches of the same profile rewrite each other's `settings.json`, `mcp.json`, and `pid`, and in-session switching rewrites a directory another live session is using.
- After an in-session `/profile use`, the directory name no longer matches its content: `instances/review/agent` holds `implement`'s configuration.
- The existing sweep implementation scans `<agentDir>/pi-profile/runtime/launch-*`, which differs from the instance path, so it is a permanent no-op in production and dead directories are never reclaimed.

Meanwhile, directory reuse accidentally confers persistence on "third-party state created at runtime": pi-subagents' mission store lives under `<agentDir>/missions/`, so it got replicated into mutually unrelated per-profile copies (one project hash has one copy each under local `default` and `ask`, and the records have diverged).

## What Changes

- **BREAKING** The instance path changes from `instances/<profile>/agent` to a unique directory `instances/launch-<random>/` generated per launch, which is the agentDir handed to Pi; multiple launches of the same profile no longer reuse the same path.
- Sweep the instance root at startup: reclaim when the process `pid` points at has exited (`ESRCH`); keep when `pid` is alive (including `EPERM`); reclaim when there is no parseable `pid` and the directory mtime is beyond the grace period. No deletion at exit.
- Before generating the instance, ensure the `missions` directory exists in the real agentDir so it gets mirrored as a symlink inside the instance. Third-party extensions then write to real paths, so no migrating, absorbing, or rewriting of third-party files is needed.
- When reclaiming a dead instance directory, if it contains "wild entries" not generated by pi-profile (neither symlinks nor managed generated artifacts), keep the directory and print an actionable warning instead of silently destroying them.
- No legacy-shape compatibility: 0.4.x's `instances/<profile>/agent` and 0.1–0.3's `<agentDir>/pi-profile/runtime/launch-*` are neither touched by the new sweep nor migrated.
- No new user-visible configuration fields.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `launcher`: the path and reuse semantics of "Instance directory contract" are inverted; two new requirements, "Stale instance sweep" and "Instance runtime-state seed".

## Impact

- Code: `src/settings-generator.ts` (instance path and seed), `src/launcher/runtime-cleanup.ts` (sweep by `instances/launch-*` + wild-entry determination), `bin/pi-profile.ts` (sweep invocation), `src/workspace.ts` (instance root comment).
- Tests: `test/runtime-cleanup.test.ts` rewritten; assertions hardcoding instance paths in `test/settings-generator.test.ts`, `test/project-scope.integration.test.ts`, `test/mcp.integration.test.ts` changed to discovering the directory under `PI_PROFILE_SWITCH_DIR`.
- Upgrade impact: legacy 0.4.x `instances/<profile>/agent` directories are neither cleaned nor migrated and are left to the user; the mission records inside carry absolute paths pointing at old instance paths — the seed only guarantees no such paths are produced from now on.
- Concurrency: concurrent launches of the same profile no longer interfere with each other; shared state on the real agentDir (session files, mission store, package install roots) follows native Pi's concurrency semantics.

## Doc Impact

- `docs/prd.md`: none — positioning, goals, and non-goals do not involve the instance lifecycle; this change does not alter the product contract.
- `docs/architecture/overview.md`: the whole "Runtime directory" section is rewritten (path shape, pid location, seed, sweep rules, managed file table); the "Known limitations" row "fixed instance path causes concurrent launches to rewrite each other; instance directories of deleted or renamed profiles are not cleaned" is deleted and replaced with "legacy 0.4.x instance directories are untouched by the new sweep".
- `CONTEXT.md`: none — the definition of `instance` ("the runtime directory generated for one Pi process") already describes per-launch; this change merely aligns the implementation with the definition.
- `docs/adr/`: add `docs/adr/0010-per-launch-instance-lifecycle.md`, recording the per-launch instance lifecycle, the rejected persistent per-profile directory design, and the trade-off of "runtime-created state falling back to the real agentDir via seed symlinks".
